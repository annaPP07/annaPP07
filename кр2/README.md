1) Задание 18. Жадный алгоритм: максимальное независимое множество
Условие. В графе найти максимальное по размеру независимое множество вершин (никакие
две не смежны).
Алгоритм: жадный выбор вершины минимальной степени.
2) Описание работы алгоритма
   
  **Инициализация:**

   
- deleted[] — массив булевых значений, показывающий, удалена ли вершина из рассмотрения.
- result — множество, в которое будут добавляться выбранные вершины.

   **Цикл:**
На каждой итерации ищем вершину с минимальной степенью среди тех, что ещё не удалены.
 for (int i = 0; i < n; i++)
Такая стратегия мотивирована тем, что вершины малой степени “мешают” меньше другим, и их безопаснее добавлять в независимое множество.
  **Добавление вершины:**
Выбранная вершина v добавляется в result.
 result.add(v);
 deleted[v] = true;
 Она помечается как удалённая (deleted[v] = true).
Все её соседи (где adjMatrix[v][u] == 1) также помечаются как удалённые, чтобы не нарушить условие независимости (в независимом множестве не должно быть смежных вершин).
  **Завершение:**
Когда все вершины удалены (или не осталось кандидатов), цикл завершается.
 for (int u = 0; u < n; u++) 
Возвращается result — найденное независимое множество.
4) Временная сложность: O(n^3)
5) Описание временной сложности
Внешний цикл выполняется не более n раз (по одной итерации на каждую вершину).
На каждой итерации:
Мы проходим по всем n вершинам, чтобы найти ту, у которой минимальная степень.
Для каждой вершины i вычисляем степень — это цикл по n элементам.
Следовательно, нахождение вершины с минимальной степенью занимает O(n^2).
Удаление соседей — O(n).
Итого: n итераций × O(n^2) = O(n^3).
6) 18. NP-сложность
Почему мы используем приближенные алгоритмы для NP-сложных задач? Объясните суть
проблемы.
NP-сложные задачи — это вычислительно трудные задачи, для которых не известно решение за полиномиальное время. Это означает, что при увеличении размера входных данных время решения растёт экспоненциально, и уже для относительно небольших входов точное решение может требовать миллионы лет вычислений.
Именно поэтому мы используем приближённые алгоритмы — они не гарантируют оптимального решения, но позволяют найти достаточно хорошее решение за разумное время. Суть подхода в том, чтобы пожертвовать идеальной точностью ради практической применимости. Таким образом, приближённые алгоритмы — это компромисс между точностью и скоростью, необходимый для решения реальных задач на практике.
